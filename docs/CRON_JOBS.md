# Cron Jobs — DetalStudio

Всі cron-скрипти знаходяться в каталозі `cron/`. Кожен скрипт захищений від веб-доступу (`CLI only`).

## Рекомендований crontab

```bash
# Обробник черги сповіщень (кожні 5 сек через loop або щохвилини через cron)
* * * * * /usr/local/bin/php /path/to/cron/worker.php >> /path/to/logs/worker.log 2>&1

# Перевірка дедлайнів (щогодини)
0 * * * * /usr/local/bin/php /path/to/cron/check_deadlines.php >> /path/to/logs/cron.log 2>&1

# Щоденні звіти (о 09:00)
0 9 * * * /usr/local/bin/php /path/to/cron/send_daily_reports.php >> /path/to/logs/cron.log 2>&1

# Очищення логів (о 04:00)
0 4 * * * /usr/local/bin/php /path/to/cron/cleanup_logs.php >> /path/to/logs/cron.log 2>&1

# Очищення БД (щотижня, неділя о 03:00)
0 3 * * 0 /usr/local/bin/php /path/to/cron/cleanup_db.php >> /path/to/logs/cron.log 2>&1
```

> Docker: worker запускається як окремий контейнер (`worker` service в docker-compose).

## Скрипти

### 1. `worker.php` — Фоновий обробник

**Інтервал**: Безперервний loop (sleep 5с між ітераціями)
**Призначення**: Обробка черги сповіщень + запуск бекапів за розкладом.

**Що робить**:
1. Обробляє до 10 записів з `notification_queue` за ітерацію
2. Перевіряє час бекапу (`BACKUP_TIME`) — якщо настав і сьогодні ще не робився → запускає `BackupService::run()`
3. Записує дату останнього бекапу в `cron/last_backup.txt`

**Graceful shutdown**:
- SIGTERM / SIGINT (pcntl)
- Файл `cron/worker.stop` — якщо існує, worker зупиняється

**Відновлення при помилках**:
- `Database::reset()` при втраті з'єднання
- `sleep(10)` при помилках для запобігання tight loop

---

### 2. `check_deadlines.php` — Перевірка дедлайнів

**Інтервал**: Щогодини
**Призначення**: Виявлення прострочених задач та відправка сповіщень.

**Що робить**:
1. Отримує всі прострочені задачі через `Task::getOverdue()`
2. Перевіряє чи сповіщення вже було відправлено (останні 2 години)
3. Якщо ні — диспатчить `DeadlineReached` event → TelegramListener відправляє повідомлення

---

### 3. `send_daily_reports.php` — Ранкові звіти

**Інтервал**: Щодня о 09:00
**Призначення**: Персоналізовані ранкові звіти кожному користувачу в Telegram.

**Що робить**:
1. Знаходить всіх активних користувачів з прив'язаним Telegram
2. Для кожного формує звіт:
   - 📅 Задачі на сьогодні
   - ⚠️ Прострочені задачі
   - 🆕 Нові замовлення (для менеджерів)
   - 💰 Дохід за місяць (для директора)
3. Відправляє через `Telegram::sendMessage()` в особисті повідомлення

---

### 4. `backup_database.php` — Бекап БД

**Інтервал**: По запиту або через worker
**Призначення**: Створення дампу MySQL бази даних.

**Що робить**:
1. Виконує `mysqldump` для створення SQL-дампу
2. Зберігає в `backups/` директорію
3. Логує результат

---

### 5. `backup_drive.php` — Бекап на Google Drive

**Інтервал**: Щодня о 03:00 (через worker)
**Призначення**: Повний бекап (БД + файли) на Google Drive.

**Що робить**:
1. Створює дамп БД
2. Створює ZIP-архів (дамп + `uploads/`)
3. Завантажує на Google Drive (Service Account)
4. Видаляє локальну копію
5. Ротація: зберігає 7 останніх копій, старі видаляє

---

### 6. `cleanup_db.php` — Очищення БД

**Інтервал**: Щотижня
**Призначення**: Видалення застарілих даних.

**Що робить**:
1. Видаляє старі записи з `notification_queue` (status = completed/failed, старше 30 днів)
2. Видаляє старі записи з `telegram_notifications`
3. Очищує orphaned records
4. Оптимізує таблиці

---

### 7. `cleanup_logs.php` — Очищення логів

**Інтервал**: Щодня о 04:00
**Призначення**: Ротація та видалення старих файлів логів.

---

### 8. `process_queue.php` — Обробка черги

**Інтервал**: Щохвилини (альтернатива worker.php)
**Призначення**: Одноразова обробка черги сповіщень (для cron замість постійного worker).

---

### 9. `fix_db_schema.php` — Ремонт схеми

**Інтервал**: По запиту
**Призначення**: Перевірка та автоматичне виправлення схеми БД (відсутні колонки, індекси).

---

### 10. `backup.php` / `backup_pdo.php` — Legacy бекапи

> ⚠️ **DEPRECATED**: Використовуйте `backup_database.php` або `backup_drive.php`.

---

## Безпека

Всі cron-скрипти захищені:
- `php_sapi_name() !== 'cli'` — відмова при HTTP доступі
- `.htaccess` в каталозі `cron/` — `Deny from all`
- Логування помилок у `logs/` або stdout
