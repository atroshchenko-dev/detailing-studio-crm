# DetalStudio — Керівництво Користувача та Розробника

## 1. Вступ

DetalStudio — спеціалізована CRM/ERP система для управління студією автодетейлінгу. Система автоматизує облік замовлень, клієнтів, автомобілів, задач, складських залишків, закупівель, фінансову аналітику, а також має глибоку інтеграцію з Telegram Bot, Google Calendar та Google Drive.

**Версія**: 1.0.2
**Технології**: PHP 8.0+ (custom MVC), MySQL 8.0+, Composer
**Детальна документація**: [`docs/`](docs/) — архітектура, API, моделі, БД

## 2. Інструкція Користувача

### 2.1 Ролі та Доступ

Система має три рівні доступу:

1. **Директор (Director)**: Повний доступ до всіх модулів — фінанси, звіти, налаштування, бекапи, аудит. Може видаляти замовлення, погоджувати закупівлі.
2. **Менеджер (Manager)**: Управління замовленнями, клієнтами, задачами, складом, закупівлями. Обмежений доступ до фінансових звітів. Може створювати виплати виконавцям.
3. **Виконавець (Executor)**: Доступ лише до своїх задач та розкладу. Бачить перелік робіт, але не фінансову інформацію по замовленнях. **Телефони клієнтів приховані (маскуються)** по всій системі, включаючи відображення у Web-інтерфейсі, пошук, Telegram-групи та Google Calendar. Має доступ до «📊 Мій заробіток» через бота.

### 2.2 Модуль «Замовлення»

- **Створення**: Кнопка «Додати замовлення». Можна обрати існуючого клієнта/авто або створити нових «на льоту».
- **Конструктор послуг**: При створенні замовлення — вибір послуг із каталогу, зміна ціни, кількості, кастомне ціноутворення.
- **Статуси**:
    - `Нове` — замовлення створено, але не погоджено.
    - `Погоджено` — клієнт дав згоду, час заброньовано.
    - `В роботі` — автомобіль в роботі.
    - `Очікує клієнта` — роботи завершені, авто готове до видачі.
    - `Закрито` — авто видано, розрахунок проведено.
    - `Скасовано` — замовлення відмінено.
- **Kanban Дошка**: Перетягуйте картки замовлень між колонками для швидкої зміни статусу.
- **Платежі**: Часткові оплати (готівка, карта, ФОП) з історією платежів.
- **Фото**: Завантаження фото «до/після/процес» з автосинхронізацією на Google Drive.
- **Google Calendar**: При створенні замовлення з дедлайном, подія автоматично додається в Google Календар студії.

### 2.3 Модуль «Задачі»

- Задачі можуть бути **автономні** або **прив'язані до замовлення**.
- **Автономна прибутковість**: Автономні задачі можуть генерувати дохід для студії незалежно від замовлень. Мають власний фінансовий облік зі статусом «Закрито».
- **My Tasks**: Розділ для виконавців — лише свої задачі на сьогодні/тиждень.
- **Автоматичні задачі**: При додаванні певних послуг у замовлення, система автоматично створює відповідні задачі для виконавців.
- **Комісії виконавців**: Кожній задачі може бути призначена сума комісії виконавця. Після завершення — комісія додається до балансу боргу перед виконавцем.
- **Календар задач**: Окремий вид відображення задач у календарному форматі.

### 2.4 Склад та Матеріали

- **Прихід**: Додавання матеріалів через накладні (зв'язок з постачальником).
- **Списання**:
    - Ручне списання.
    - Списання під замовлення або задачу (матеріали прив'язуються до конкретного авто/задачі).
- **Мінімальні залишки**: Автоматичне сповіщення при досягненні мінімального рівня.
- **Категорії**: матеріали, витратники, інструменти.

### 2.5 Фінанси та Звіти

- **Dashboard (Аналітика)**:
    - **Сьогодні**: Оперативна зведення за день (нові замовлення, виконані, каса, дедлайни).
    - **Ключові показники**: Картки з динамікою замовлень, доходу, задач та стану складу.
    - **Графік**: Візуалізація доходів та виконаних задач за останні 6 місяців.
    - **Топ послуг та клієнтів**: Рейтинг найпопулярніших послуг та найактивніших клієнтів.
- **Звіти**: Детальна аналітика по доходах, витратах, ефективності менеджерів та популярності послуг.
- **Виплати**: Облік комісій виконавців та виплат/авансів. Функція **«Закрити день»** — агрегує всі невиплачені комісії по виконавцях та дозволяє здійснити виплату одним кліком.
- **Інші витрати**: Окремий модуль для обліку бізнес-витрат (оренда, комунальні тощо).

### 2.6 Глобальний Пошук

В шапці сайту доступний глобальний пошук, який шукає співпадіння одночасно в кількох розділах:
- **Замовлення**: За номером замовлення.
- **Клієнти**: За ім'ям або номером телефону.
- **Авто**: За держ. номером, VIN-кодом, маркою або моделлю.
- **Задачі**: За назвою задачі.

### 2.7 Telegram Bot

Система має повноцінного Telegram-бота, який дозволяє:
- **Отримувати сповіщення** — автоматичні повідомлення про нові замовлення, задачі, зміни статусів, дедлайни. Кожна категорія йде у свій топік (thread) супергрупи.
- **Створювати замовлення та задачі** — покрокові Wizards прямо в чаті бота.
- **Змінювати статуси** — через inline-кнопки під повідомленнями.
- **Переглядати свої задачі/замовлення** — команди `/my_tasks`, `/my_orders` з пагінацією.
- **Фінансові операції** — «📊 Мій заробіток» (для виконавців), «💸 Закрити день» (для менеджерів/директорів), «💳 Історія виплат».
- **Вибирати дати** — інтерактивний inline-календар з навігацією по місяцях.

## 3. Технічне Керівництво (Для Розробника)

> Повна технічна документація: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

### 3.1 Системні Вимоги

- **OS**: Linux (Ubuntu/Debian) або Windows (через Docker).
- **Web Server**: Apache або Nginx.
- **PHP**: 8.0+ (рекомендовано 8.1+)
    - Extensions: `pdo`, `pdo_mysql`, `mbstring`, `curl`, `gd`, `zip`, `xml`.
- **Database**: MySQL 8.0 або MariaDB 10.5+.
- **Composer**: Для управління залежностями.

### 3.2 Архітектура

Проект побудований на архітектурі **MVC** без використання важких фреймворків. Ключові архітектурні рішення:

**Namespace**: `App\` → `includes/` (PSR-4 через Composer autoload)

**Шари системи**:

| Шар | Каталог | Опис |
|-----|---------|------|
| Models | `includes/Models/` | Робота з БД, бізнес-логіка (12 класів) |
| Controllers | `includes/Controllers/` | Обробка HTTP-запитів (2 класи) |
| Services | `includes/Services/` | Складна бізнес-логіка (OrderService, TaskService) |
| Events | `includes/Events/` | Доменні події (13 класів + EventDispatcher) |
| Listeners | `includes/Listeners/` | Реакції на події (Telegram, Google, TaskCompletion) |
| Traits | `includes/Traits/` | PHP traits для Telegram-бота та Order-логіки |
| Views | `views/` | HTML шаблони (layout, components, errors) |
| API | `api/` | AJAX ендпоінти (18 файлів) |

**Event-Driven Architecture**:
Система використовує патерн Event/Listener для відділення бізнес-логіки від побічних ефектів. При зміні замовлення/задачі — автоматично відправляються Telegram-повідомлення, оновлюється Google Calendar, виконуються перевірки завершення тощо.

- `EventDispatcher` — реєстрація та диспетчеризація подій
- `events_init.php` — файл реєстрації всіх слухачів
- Повний перелік подій: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)

**Aliases (зворотна сумісність)**:
Файл `includes/aliases.php` створює глобальні аліаси класів (`Order` → `App\Models\Order`), що дозволяє використовувати короткі імена у view-файлах.

### 3.3 База Даних

Використовується MySQL. Схема: [docs/DATABASE.md](docs/DATABASE.md)

**Основні таблиці**:
- `users` — Користувачі та ролі (director, manager, executor)
- `orders`, `order_items`, `order_payments`, `order_comments`, `order_photos` — Замовлення
- `clients`, `cars` — Клієнти та авто
- `tasks`, `task_comments` — Задачі
- `services`, `service_categories` — Каталог послуг
- `warehouse_items`, `warehouse_transactions` — Склад
- `purchase_requests`, `purchase_request_items` — Закупівлі
- `suppliers` — Постачальники
- `employee_payments` — Виплати співробітникам
- `audit_log` — Аудит-лог
- `notification_queue`, `telegram_notifications` — Черга сповіщень
- `settings` — Системні налаштування

**Views**: `v_order_totals`, `v_task_overview`, `v_warehouse_balance`

**Міграції**: `config/migrations/` — 38 файлів (SQL та PHP). Нумерація послідовна (`001_`, `002_`, ..., `035_`). Запуск через `migrate.php`.

### 3.4 Інтеграції

#### Google Cloud
Бібліотека: `google/apiclient` v2.15+. Клас: `App\GoogleIntegration`.

- **Calendar**: Синхронізація дедлайнів замовлень та задач. Методи: `createOrderCalendarEvent`, `updateOrderCalendarEvent`, `deleteCalendarEvent`.
- **Drive**: Створення папок для фотозвітів, завантаження файлів. Service Account authentication.

#### Telegram Bot
Архітектура: клас `App\Telegram` використовує **traits** для розділення відповідальності:

| Trait | Файл | Відповідальність |
|-------|------|------------------|
| `TelegramApi` | `Traits/TelegramApi.php` | Низькорівневі HTTP-запити до Bot API |
| `TelegramCommands` | `Traits/TelegramCommands.php` | Обробка команд та меню |
| `TelegramWebhook` | `Traits/TelegramWebhook.php` | Обробка вхідних webhook запитів |
| `TelegramNotifications` | `Traits/TelegramNotifications.php` | Відправка сповіщень (sync) |

**Wizards** (покрокове створення через чат):
- `OrderWizard` — створення замовлення (клієнт → авто → послуги → дедлайн)
- `TaskWizard` — створення задачі (назва → виконавець → пріоритет → дедлайн → комісія)
- `FinanceWizard` — фінансові операції (виплати, закриття дня)

**UI Constants**: Клас `App\BotConstants` централізує всі emoji та текстові рядки кнопок, щоб запобігти помилкам webhook через незначні відмінності в тексті.

**Topics (Threads)**: Повідомлення розподіляються по топіках супергрупи:
- Orders (TELEGRAM_TOPIC_ORDERS)
- Tasks (TELEGRAM_TOPIC_TASKS)
- Finance (TELEGRAM_TOPIC_FINANCE)
- Alerts (TELEGRAM_TOPIC_ALERTS)
- General (TELEGRAM_TOPIC_GENERAL)

### 3.5 Безпека

- **CSRF Protection**: Всі POST запити захищені токеном (`App\Csrf`). AJAX: meta tag + jQuery auto-header.
- **XSS Protection**: Глобальний helper `e()` для HTML escaping. `htmlspecialchars()` у views.
- **SQL Injection**: Тільки підготовлені запити (PDO prepare/execute).
- **Auth**: PHP сесії, `password_hash()` / `password_verify()`, мінімальна довжина пароля 8 символів.
- **Remember Token**: SHA-256 хеш зберігається в БД; сирий токен — тільки в cookie. Захист від session hijacking при компрометації БД.
- **Rate Limiting**: `App\RateLimiter` — IP-based, 5 запитів / 10 хв на публічних ендпоінтах.
- **Session Hardening**: `cookie_httponly`, `cookie_secure`, `cookie_samesite=Lax`.
- **Security Headers**: HSTS, X-Frame-Options SAMEORIGIN, X-Content-Type-Options nosniff.
- **Telegram Webhook**: Валідація `X-Telegram-Bot-Api-Secret-Token`.
- **Directory Protection**: `.htaccess` deny для `/tools`, `/cron`, `/backups`, `/logs`, `/config`.

### 3.6 Cron Jobs (Планувальник)

Повна документація: [docs/CRON_JOBS.md](docs/CRON_JOBS.md)

```bash
# Обробник черги сповіщень (щохвилини)
* * * * * php /path/to/cron/worker.php > /dev/null 2>&1

# Перевірка дедлайнів задач (щогодини)
0 * * * * php /path/to/cron/check_deadlines.php

# Щоденний бекап на Google Drive (о 03:00)
0 3 * * * php /path/to/cron/backup_drive.php

# Щоденні звіти
0 8 * * * php /path/to/cron/send_daily_reports.php

# Очищення логів (щодня о 04:00)
0 4 * * * php /path/to/cron/cleanup_logs.php
```

### 3.7 Конфігурація

Секрети зберігаються в `.env` файлі (завантажується через `vlucas/phpdotenv`). Приклад: `.env.example`.

Всі константи визначаються в `config/config.php` з fallback значеннями:
```php
define('DB_HOST', $_ENV['DB_HOST'] ?? 'localhost');
```

- **Аудит-лог**: Перегляд всіх дій користувачів (`admin/audit_logs.php`).

- **Стійла/бокси**: Управління робочими місцями (`admin/stalls.php`).

## 4. Troubleshooting (Вирішення проблем)

### «500 Internal Server Error»
1. Перевірте файл логів: `logs/app.log` (Monolog).
2. Переконайтесь, що `.env` містить коректні дані доступу до БД.
3. Перевірте права доступу до папок `logs/`, `uploads/`, `backups/` (755 для директорій, 644 для файлів).

### «Google API Error»
1. Перевірте наявність файлу `config/google_service_account.json`.
2. Переконайтесь, що сервісний акаунт має доступ до Google Calendar (Share calendar with service account email).
3. Перевірте що Google Calendar API та Google Drive API увімкнені в Google Cloud Console.

### «Cannot declare class...»
1. Це часто виникає при дублюванні імен класів або неправильному Autoload.
2. Виконайте `composer dump-autoload -o`.
3. Перевірте `includes/aliases.php` на конфлікти.

### «Telegram bot не відповідає»
1. Перевірте webhook: `curl https://api.telegram.org/botTOKEN/getWebhookInfo`
2. Перевірте `TELEGRAM_WEBHOOK_SECRET` у `.env`.
3. Переконайтесь що URL webhook доступний через HTTPS.
4. Перевірте логи: `logs/telegram_webhook.log` — фатальні помилки перехоплюються `register_shutdown_function`.
5. **Imunify360 блокування**: Хостинг може автоматично блокувати IP Telegram. Перевірте доступність підмереж:
   - `149.154.160.0/20`
   - `91.108.4.0/22`
   - `91.108.56.0/22`
   Зверніться до підтримки хостингу для додавання в White List.
6. **rate_limit конфлікт**: Якщо wizards не реагують на текст (відповідає «Я не розумію»), перевірте таблицю `telegram_conversations` — можливо є застарілий запис з `step = 'rate_limit'`.

### «Cron не працює»
1. Перевірте шлях до PHP: `which php` або `/usr/local/bin/php`.
2. Перевірте що скрипти запускаються з CLI: `php cron/worker.php`.
3. Перевірте логи cron: `grep CRON /var/log/syslog`.
